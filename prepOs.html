Sliding window \'97 variable size
def sliding_window(s):\
    left = 0; window = \{\}; ans = 0\
    for right in range(len(s)):\
        window[s[right]] = window.get(s[right], 0) + 1\
        while window_invalid(window):\
            window[s[left]] -= 1\
            if not window[s[left]]: del window[s[left]]\
            left += 1\
        ans = max(ans, right - left + 1)\
    return ans

def backtrack(start, path, result):\
    result.append(path[:])          # record state\

        path.append(nums[i])        # choose\

Union-Find with path compression + rank
parent = list(range(n)); rank = [0]*n\
def find(x):\
    if parent[x] != x: parent[x] = find(parent[x])\
    return parent[x]\
def union(x, y):\
    px, py = find(x), find(y)\
    if px == py: return False\
    if rank[px] < rank[py]: px, py = py, px\
    parent[py] = px\
    if rank[px] == rank[py]: rank[px] += 1\
    return True
\
Dijkstra shortest path
import heapq\
def dijkstra(graph, src, n):\
    dist = [float('inf')] * n; dist[src] = 0\
    heap = [(0, src)]\
    while heap:\
        d, u = heapq.heappop(heap)\
        if d > dist[u]: continue\
        for v, w in graph[u]:\
            if dist[u] + w < dist[v]:\
                dist[v] = dist[u] + w\
                heapq.heappush(heap, (dist[v], v))\
    return dist
\
KMP string search
def kmp(text, pattern):\
    lps = [0] * len(pattern); j = 0\
    # build failure function\
    for i in range(1, len(pattern)):\
        while j > 0 and pattern[i] != pattern[j]: j = lps[j-1]\
        if pattern[i] == pattern[j]: j += 1\
        lps[i] = j\
    # search\
    j = 0\
    for i in range(len(text)):\
        while j > 0 and text[i] != pattern[j]: j = lps[j-1]\
        if text[i] == pattern[j]: j += 1\
        if j == len(pattern): return i - j + 1\
    return -1

\uc0\u55357 \u56589 How to solve any DSA problem \'97 the exact thinking process
\
\ This process works for every problem at every difficulty. Follow it in order every time \'97 especially in real interviews. Interviewers score your thinking, not just your code.\
\ \
\ \
\
1
\
\
Read and restate \'97 2 minutes
\
Say the problem out loud in your own words. Ask clarifying questions before writing any code: What are the constraints? Can input be empty? Negative numbers? Duplicates? Sorted or unsorted? What should we return if no answer exists?
\ In an interview this is mandatory. In practice it forces you to actually understand the problem before jumping to a solution.
\
\
\ \
\
2
\
\
Brute force first \'97 always, out loud \'97 3 minutes
\
Do not skip this step. Say: "The naive approach would be..." and describe it without coding it. Usually O(n\'b2) or O(n\'b3). This does three things: proves you understand the problem, gives you a baseline to optimise from, and impresses interviewers who see most candidates skip straight to a broken optimised solution.
\ Example: Two Sum brute force = check every pair of numbers = O(n\'b2) time O(1) space. State this explicitly.
\
\
\ \
\
3
\
\
Spot the bottleneck in your brute force \'97 3 minutes
\
Look at your brute force and ask: "Where is the repeated work?" This single question unlocks the optimisation. The repeated work maps directly to a pattern:
\
\
Nested loops scanning same subarray
\uc0\u8594 Sliding window or two pointers
\
Re-computing the same subproblem
\uc0\u8594 Dynamic programming
\
Searching in sorted data linearly
\uc0\u8594 Binary search
\
Looking up "have I seen this before"
\uc0\u8594 HashMap / HashSet
\
Need min/max of current window
\uc0\u8594 Monotonic stack/deque or heap
\
Traversing connected nodes/paths
\uc0\u8594 DFS / BFS / Union-Find
\
\
\
\ \
\
4
\
\
State the optimal approach before coding \'97 2 minutes
\
Say: "I'll use a sliding window with a hashmap. Time O(n), Space O(k) where k is alphabet size." State the complexity before writing a single line. This proves you know what you're doing and gives the interviewer a chance to correct you before you go down a wrong path for 20 minutes.
\
\
\ \
\
5
\
\
Code it \'97 talk while you write \'97 15\'9625 minutes
\
Now write the code. Talk while you type. Say what you're doing: "I'm initialising left pointer at 0, I'll expand right on each iteration, when the window becomes invalid I shrink from the left..."
\ Silence during coding = the interviewer can't tell if you're stuck or thinking. Keep narrating. Write clean, readable variable names \'97 not x and y, use left and max_window.
\
\
\ \
\
6
\
\
Test with the example, then your own edge case \'97 5 minutes
\
Dry-run the given example on paper. Then test your own edge case: empty input, single element, all duplicates, already sorted, all same value, negative numbers. Catch bugs before the interviewer does \'97 this alone separates good candidates from great ones.
\
\
\ \
\
7
\
\
After solving \'97 write the pattern in your note
\
Immediately click \uc0\u9998 and write: Pattern: [name]. Key insight: [one sentence]. Edge case: [one case]. After solving 50 problems this way, you will have a personalised pattern library that is worth more than any paid course. The pattern list is small \'97 there are about 15 patterns total. Every new problem is just a variant of one you've seen.
